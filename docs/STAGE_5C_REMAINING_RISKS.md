## 3. Deep-Dive: External Onboarding Requirements

### 3.1 Meta WhatsApp Business API Prerequisites
1. **Meta Business Verification:**
   - The gym or platform entity must complete official business verification (submitting business license, tax certificate, utility bills) in Meta Business Manager.
2. **Template Classification ("Utility"):**
   - Renewal reminders, payment notices, and expiry alerts must be submitted under the `UTILITY` category.
   - If submitted as `MARKETING`, costs are significantly higher, and messaging is restricted outside user-initiated 24-hour windows.
   - The template text submitted to Meta must match the parameters generated by `server/services/reminders/adapters/whatsappAdapter.ts`.
3. **Opt-in / Consent Policy:**
   - Members must explicitly opt in to receive WhatsApp notifications during member registration or profile update. FITFUSION’s schema correctly provides `whatsapp_opt_out` and `sms_opt_out` flags to respect member preferences.

### 3.2 Indian Telecom Commercial SMS (TRAI DLT) Prerequisites
Under Telecom Regulatory Authority of India (TRAI) regulations (TCCCPR 2018), sending transactional or service-implicit SMS to Indian mobile numbers (`+91`) mandates:
1. **Principal Entity (PE) Registration:**
   - Register the business on an Indian telecom DLT portal.
   - Obtain a unique 19-digit Principal Entity ID.
2. **Header (Sender ID) Registration:**
   - Register a 6-character alpha sender header (e.g., `FITFUS`, `FFGYMS`).
3. **Template Registration (PE-TM Binding):**
   - Register the exact reminder SMS template text with variable placeholders (e.g., `Dear {#var#}, your gym membership {#var#} expires on {#var#}.`).
   - Associate the Template ID with AWS Pinpoint / SMS gateway configuration.
   - Failure to pass matching DLT Template IDs results in telco carrier drops.

### 3.3 Live Inbound Webhook Configuration
- Meta requires a public URL responding to `GET /api/webhooks/whatsapp` with the configured `hub.verify_token`.
- Incoming status callbacks (`POST /api/webhooks/whatsapp`) require raw body signature validation via `x-hub-signature-256`.
- The webhook endpoint implemented in Stage 5B handles this completely. For production deployment, configure reverse proxy routing to ensure the raw binary body is made available for HMAC-SHA256 signature evaluation before JSON parsing.

## 4. Recommended Production Deployment Sequence

To transition from Stage 5C code readiness to live production rollout:

1. **Phase 1: Staging Smoke Testing (Internal Numbers Only)**
   - Add test staff phone numbers to Meta WhatsApp test recipient list.
   - Deploy code to staging with `CRON_SECRET` configured.
   - Trigger manual test cron runs and verify WhatsApp test template delivery on real handsets.
2. **Phase 2: Regulatory & Provider Approval**
   - Submit Meta WhatsApp templates for Utility review.
   - Complete TRAI DLT registration and configure Template IDs in AWS Pinpoint.
3. **Phase 3: Controlled Tenant Pilot**
   - Enable automated cron for a single pilot gym tenant with conservative batch sizes (`BATCH_SIZE=10`).
   - Monitor database telemetry (`GET /api/reminders/telemetry`) and audit logs for 7 days.
   - Verify zero double dispatches and healthy delivery rates.
4. **Phase 4: Full Multi-Tenant Rollout**
   - Enable automated cron across all gym tenants with standard 10-minute cadence.
